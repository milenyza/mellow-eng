# Practical English

The catalog at `/ingles-na-pratica` groups A1 situations by what a learner wants to do. Its eight categories cover airports, hotels, food and drink, shopping, transportation, introductions, health and emergencies, and getting around a city. The first collection offers two scenario outlines per category. All eight situations are previewable. The airport, hotel, and food and drink phrasebooks are available with 18, 19, and 19 A1 expressions respectively. Each of those three situations also offers two interactive dialogues and two guided simulations. The other five situations are preview-only. Dedicated cultural guidance remains upcoming.

## Learning approach

Curriculum lessons introduce and build on language patterns in sequence. Practical English starts with a communicative purpose, such as asking where the boarding gate is or confirming a reservation. Learners should be able to consult an expression quickly or study an entire published situation without passing prerequisite lessons.

Teach a small set of useful phrases in context. Explain whom the learner is speaking to and when a response sounds neutral, informal or formal. Show natural alternatives with context-specific feedback when multiple replies work. Provide cultural guidance with a clear context and avoid presenting local conventions as universal rules. Health and emergency scenarios teach how to ask for help and communicate basic information.

Structured reading uses short dialogues with optional Brazilian Portuguese translations and on-demand pronunciation. Guided simulations ask learners to choose how to respond in the same kinds of situations, with explicit feedback and authored alternative paths. A scenario can demonstrate practice in a particular context. Its completion does not establish language mastery.

## Architecture

- `frontend/src/types/practical-english.ts` defines the publication states, categories, scenario outlines, expressions, dialogues and cultural guidance. Phrasebooks, dialogues and simulations can be released independently of full-situation publication. `frontend/src/types/conversation.ts` defines the guided conversation graph, learner actions recorded by the engine and the result model.
- `frontend/src/data/practical-english.ts` holds static catalog metadata, objectives and scenario outlines. Use stable kebab-case IDs for categories, situations, scenarios and future entries. Change display titles without changing IDs. References point to existing lessons, stories or vocabulary and carry no prerequisite behavior.
- `frontend/src/services/practical-english-catalog.ts` filters content by category and search terms. Search is case- and accent-insensitive and matches both titles and authored keywords. The service accepts plain data, so a future API adapter can supply the same catalog model.
- The route in `pages/practical-english-page.tsx` and the components under `components/practical-english/` render catalog controls and native previews. Decorative SVG illustrations are stored locally under `assets/practical-english/` and mapped by category. Catalog interactions do not read or write learner records. The detail route at `/ingles-na-pratica/:situationId` reads and writes expression favorites only when the learner uses the favorite control.

The phrasebook model reuses `CefrCode`, the bilingual `TranslatedExample` and `AudioSource`. Each expression has an ID and a communicative intent. This supports grouping and filtering by communicative purpose. The phrasebook search indexes English, Brazilian Portuguese, context, and explicit keywords. Related expressions use stable expression IDs. Data remains independent of presentation, conversation rules and learner state.

## Loading and favorites

The hub loads catalog metadata and artwork. The detail route loads its page on demand and uses a loader to fetch only the requested phrasebook module. Preview-only and unknown IDs render local fallbacks. The Dashboard and lesson catalog use an A1 index without activity blocks. The Lesson Player loads its route and full curriculum only when needed. Vite's warning threshold is unchanged.

The phrasebook shares one speech playback instance and uses rates of 1.0 and 0.75. Changing a filter or speed stops the active utterance, and leaving the page cancels it. Audio is generated by the browser. The automated tests simulate speech synthesis, and audible playback depends on the browser's installed voices.

Favorites continue to use the existing JSON array of IDs at `mellow:favorite-words`. Practical expression IDs are namespaced as `practical-<situation-id>-<entry-slug>`. A future Notebook can resolve these IDs through the same phrasebook loaders. The stored identifier represents the whole expression, including multi-word phrases.

## Interactive dialogues

A dialogue is directly addressable at `/ingles-na-pratica/:situationId/dialogos/:dialogueId`. The situation shows a lightweight index of titles. The reader resolves only the requested situation's dialogue module and its published phrasebook. Unknown or cross-situation IDs show a local fallback. The learning sequence imposes no prerequisites.

The audio adapter builds an ordered source from stable turn and participant IDs. It uses the shared Web Speech service and advances only on each utterance's `end` event. The `start` event sets the highlighted turn. Starting a different recording or changing speed stops the current one. Navigating away cancels it, and callbacks from cancelled utterances are ignored.

The browser voice list is queried again for each playback. A run keeps one allocation for the ordered participants, prefers en-US voices and uses other English voices as fallbacks. With one English voice it is shared. If voices are still loading, the current run uses the browser default for en-US. The next playback can use voices that became available meanwhile. Pause and resume appear when the browser exposes those controls and reports its pause state. The interface checks the state after a request. Audio behavior is covered with simulated browser events.

Translations are initially hidden. Individual and global controls change local reading state. The expression list resolves IDs from the dialogue against its phrasebook. Its favorite action stores the existing phrase ID and deep-links back to that entry. No dialogue state is saved.

## Guided conversation simulations

Open a simulation at `/ingles-na-pratica/:situationId/simulacoes/:scenarioId` or from the situation's simulation list. The list imports only summaries. The route lazily loads the player, then requests only the selected situation's authored graphs and published phrasebook. Invalid and cross-situation IDs return a fallback without fetching a graph. A scenario must pass graph validation and resolve its outline (when specified), dialogue and phrasebook references before it can open.

The six A1 simulations cover flight check-in, boarding gate directions, hotel arrival, reception assistance, a restaurant meal, and coffee to go. Each successful path has four learner decisions. For example, showing a passport or giving the flight number first prompts a different follow-up at check-in. Ordering a small or large coffee changes the price.

A shared state transition function handles selection, explicit submission, deterministic branching, hints, retries and correction review. Only appropriate choices advance. A context distractor is well-formed English for a different need. A language distractor needs an English correction. Learners can retry or explicitly choose an appropriate response after reviewing the correction. The transcript includes only visited turns and identifies replies chosen during review. Choices shuffle within each session without changing what they do.

Playback uses the shared audio abstraction with a stable speaker roster for every line, takes place on demand at 1.0 or 0.75, and cancels on node change, restart or exit. Translations are initially hidden. Results show decisions, submissions, decisions answered appropriately on the first submission, unique hints used, corrections reviewed and estimated active time while the tab is visible, focused and recently used. A reviewed option does not count as a new answer submission. Sessions and results stay in memory. Saving an expression intentionally updates the existing favorites list using its phrasebook ID.
